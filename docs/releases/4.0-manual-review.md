# LiftPath 4.0 Manual Mobile Review

This checklist records release evidence that cannot be established solely by TypeScript, jsdom, headless Chromium or axe. Do not mark an item complete without naming the device/browser and recording the result.

- [x] Chromium viewport 360 × 800: onboarding, readiness, workout, recap and migration flows exercised by Playwright.

## Onboarding

- [ ] Every step has one obvious primary action and a visible progress indicator.
- [ ] Vietnamese copy wraps without clipping at 360 px.
- [ ] Equipment choices, preferred days and restrictions remain selected when navigating backward.
- [ ] The preview shows one equipment-safe plan and its explanations before confirmation.
- [ ] Soft keyboard does not cover the final profile-notes field or primary action.

## Readiness and safety

- [ ] Normal readiness starts the unchanged planned workout.
- [ ] Low energy with 35 minutes visibly removes later non-primary work while retaining both primary movements.
- [ ] High soreness reduces effort guidance without mutating the underlying template.
- [ ] Sharp knee pain blocks the affected session and displays the non-diagnosis copy.
- [ ] Browser API failures do not prevent readiness confirmation or set logging.

## Set entry and workout editing

- [ ] Previous corresponding values are visible inline and copy with one tap.
- [ ] A valid set completes with effort left blank.
- [ ] Numeric soft keyboards appear for load, reps, seconds and distance fields.
- [ ] Quick load buttons, complete/undo, add/remove set and exercise editing remain at least 44 px.
- [ ] No control or focused input is hidden behind browser chrome or a bottom safe area.
- [ ] Bodyweight, assisted, weighted-bodyweight, duration and distance modes show only compatible fields.

## Timer, vibration and Wake Lock

- [ ] Completing a set starts the correct rest timer.
- [ ] ±15 seconds and skip controls work while the timer is active.
- [ ] Notification/vibration denial does not block logging.
- [ ] Wake Lock success state appears when supported.
- [ ] Wake Lock failure or unsupported state leaves the workout fully usable.

## Recap and persistence

- [ ] Recap presents what went well, attention and next-time changes before raw metrics.
- [ ] Every next-time decision includes an explanation.
- [ ] Closing and reopening the app preserves history, explicit exercise preferences and the saved recap snapshot.
- [ ] Dark and light modes both maintain readable contrast and visible focus.

## PWA and offline behavior

- [ ] Install prompt/installation works from a production HTTPS deployment.
- [ ] Installed app launches with LiftPath 4.0 name, icon and standalone display.
- [ ] Reloading the installed app while offline loads the shell.
- [ ] Existing locally stored workout history remains available offline.
- [ ] A new deployment updates the service worker without trapping the app on stale assets.

## Migration from v3

- [ ] Copy a real or sanitized v3 payload before testing.
- [ ] Launch 4.0 and verify history count, body stats, custom exercises and custom programs.
- [ ] Resume an active migrated draft, complete a set and finish the workout.
- [ ] Export JSON after migration and confirm schema version 4 with no bearer token.
- [ ] Record any migration warnings and verify they isolate only malformed records.

## Release decision

- [ ] All blocking manual items above are complete.
- [ ] No unresolved serious/critical accessibility violation remains.
- [ ] No P0/P1 browser or migration defect remains.
- [ ] PR exact head matches the verified CI run.
- [ ] PR is moved out of draft only after independent review.
